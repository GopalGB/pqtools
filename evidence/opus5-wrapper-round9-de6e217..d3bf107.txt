**HIGH — `src/pqtools/core.py:244` — the abandon path stopped closing stdin: leaked fd + a permanently stuck writer thread per timed-out call.**
`readers` now excludes `process.stdin`, and `process.stdin = None` two lines later stops `Popen.__exit__` from closing it either, so when a grandchild holds the stdin read end nothing ever closes the write end. Measured on the same input (child spawns a sleeping grandchild, 8 MiB payload, 2 s timeout): HEAD → 0 fds leaked, 0 live threads; staged → **1 fd leaked, `Thread-3 (write)` blocked in `write()` forever**. Repeated bridge timeouts accumulate both, and the grandchild never sees EOF. The comment's premise ("a writer blocked on a full pipe gets EPIPE") holds only when the killed child is the last holder of the read end — which is the exact case the abandon path exists *not* to assume.
*Fix:* add `process.stdin` back to the `readers` list so it is closed by the same `getattr(stream, "raw", stream).close()`. Verified: 0 fds leaked, writer exits, and it does **not** reinstate the double-close bug — the object is marked closed, so both the writer's `finally: stdin.close()` and the finaliser become no-ops. This requires relaxing `tests/test_core.py:337`, which pins the leak (`assert "process.stdin" not in readers[0]`) instead of the actual invariant already asserted above it (no `os.close`, no `.fileno`).

**MEDIUM — `src/pqtools/builtins/_number.py:1341` — ISO-only detection leaves the silent wrong answer in place for the common invariant-culture date forms, which `SUPPORT-MATRIX.md` now says are refused.**
Executed against the staged tree:
```

Value.FromText("Apr 8, 2022") -> str 'Apr 8, 2022'     Date.FromText("Apr 8, 2022") -> date(2022,4,8)
```

The docstring's justification ("ISO 8601 … the narrowest defensible reading … without inventing a format table") is contradicted by this package's own `_datetime.py:246-251`, which explicitly rejects ISO-only as "the narrowest possible reading of 'the invariant culture' and not what it means" and cites `Time.FromText("10:12:31am")` as Microsoft's own Example 1. The grammar is already owned, grounded and tested — the same argument that (correctly) drove reusing `_DURATION_TEXT_RE` applies verbatim here and was not followed. `SUPPORT-MATRIX.md` meanwhile tells a reader that text which "reads as a date, time, datetime or duration" is refused by name.
*Fix:* detect via the existing `_datetime._date_from` / `_time_from` / `_datetime_from` (try/except EvalError), same import-don't-copy pattern as the duration branch; or narrow the SUPPORT-MATRIX row to "ISO 8601 only" and record non-ISO invariant text as a still-open silent gap.
