## Verdict

**PARTIALLY FULFILLED; fixes required before claiming safe, complete support.** The library runs useful Power Query transformations and supports source tooling and container workflows. It is not full Microsoft Power Query compatibility. Registered function counts measure names, not complete argument, connector, or semantic support.

## Your requirement and how it works

The original toolkit requirements cover Python/CLI parsing, formatting, linting, dependencies, safe edits, offline operation, packaging, and optional Microsoft execution adapters. Later project requirements add the “pandas for Power Query” workflow: run real query transformations on supplied data, then connectors and workbook editing. Evidence: the original MAX HQ `.planning/max-log-recovery-powerquery-toolkit-2026-09-01/PRD.md` Track B; this repository's `ops/PRD-0.5.0-builtins.md`, `ops/STATUS.md`, `CLAUDE.md`, and current README. The historical PRDs do not form one reconciled 0.10.0 acceptance contract.

The CLI/Python API passes M source to Microsoft's bundled parser/formatter through Node. The Python evaluator walks the resulting AST and dispatches registered builtins. Local sources or `--bind` provide input tables; Python performs transformations. Network and database access require explicit policy flags. Container commands extract embedded M; write commands create a backup and replace the query content. Fabric/PQTest are separate execution adapters.

## Findings

### HIGH: backup destination can overwrite an unrelated file

`src/pqtools/cli.py:167-177` writes directly to `<container>.bak` using `Path.write_bytes`, without validating that destination. Callers create the backup before `write_sections` performs its safe-write handling (`:190-191`, also the add path). A pre-existing backup symlink is followed. In an isolated temporary directory, a dummy target containing `KEEP ME` was overwritten with dummy workbook bytes. No real user file was used.

Required correction: validate backup destinations, reject links, and use a safe atomic backup operation with an explicit existing-backup policy. Test both container write callers and failure preservation.

### HIGH: paginated OData silently loses rows

`src/pqtools/builtins/_sources.py:234-289` fetches once and returns the response's `value`; it ignores `@odata.nextLink`. A local two-page fixture returned only `[{"Id": 1}]`, losing the second page's `{"Id": 2}` without an error.

Required correction: follow pagination with the existing network policy applied at every step, with cycle/resource limits; otherwise explicitly refuse paginated responses instead of returning partial data.

### HIGH: SQL navigation reads every table before selection

`src/pqtools/builtins/_sources.py:506-523` builds the navigation table by executing `SELECT *` for every catalog entry. A mocked catalog containing `Wanted` and `Unrelated` caused both tables to be fetched. A query selecting one table can therefore fail or consume resources because of an unrelated table. Live database performance was not tested.

Required correction: make navigation data lazy or explicitly constrain the supported navigation path; verify that selecting one table never fetches unrelated data.

### MEDIUM: SQL options are silently discarded

`src/pqtools/builtins/_sources.py:479-485` discards `CommandTimeout`, `HierarchicalNavigation`, and `MultiSubnetFailover`. A mocked call accepted an invalid `CommandTimeout` value without validation or refusal. This conflicts with the documented rule that unsupported options must raise rather than be ignored (`ops/PRD-0.5.0-builtins.md`, correctness notes).

### MEDIUM: credential documentation and implementation disagree

README states credentials come from environment variables, but `_sources.py:429-439` accepts and prioritizes inline `Username`/`Password`. A test using dummy values confirmed that query options override environment values. No actual credentials were read. Align implementation and documentation with the intended environment-only requirement.

### MEDIUM: compatibility checks leave blind spots

`tests/test_doc_examples.py:168-177` returns successfully when either expression cannot evaluate, and its match floor is only 110 (`:194-212`). Green tests therefore do not mean every documentation example executed successfully. `tests/test_documented_signatures.py:33-62` only extracts literal `_arity` calls; dynamically registered PostgreSQL/MySQL connectors are omitted even though `_sources.py:589-593` accepts one required argument and their checked-in signatures require two. Use per-case expected outcomes and runtime signature checks for dynamic registrations.

### MEDIUM: current requirements and documentation contradict each other

README says several connectors do not and will not execute (`:142-146`, `:432-438`) while later sections describe them as supported (`:456-470`). `.planning/m-inventory.md` and `ops/STATUS.md` describe older implementation states. Rename also refuses common query constructs at `core.py:415-419`. Reconcile one current support matrix that distinguishes names, supported options, tested workflows, typed refusals, and unverified external integrations.
